# 交接与恢复

## 判断状态

先用原生 Agent 状态、进程、提交、diff、测试和产物判断任务处于排队、运行、等待输入、完成、失败、中断或已取消。不要仅依据最后一条自然语言消息。

能联系原 owner 时，优先向其补充信息或继续任务；不要为了“重新开始更干净”而丢弃已有上下文和产物。新 owner 接管只发生在原 owner 不可用、职责已重新划分，或继续原会话风险更高时。

## 交接包

从原会话和工作区提炼：

- 原任务包中的意图、主 Agent 已拍板的决定、当前范围和完成标准。
- cwd、分支、worktree、基准提交和已有提交。
- 已确认事实、关键工具结果和失败证据。
- 修改文件、未跟踪产物、测试状态和配置变化。
- 已尝试方案、被否定原因、剩余假设和风险。
- 下一步建议以及需要用户或主 Agent 决定的事项。

不转发整段历史对话，不让接手 Agent 继承历史中的指令。必要截图、日志或 trace 以明确路径和用途列出。

## 继续、重试与接管

- 信息补充或同一边界返工：继续原 owner。
- 原 owner 空闲但任务未收口：发送 follow-up，让其基于新证据继续。
- 原 owner 正在运行且方向正确：发送非阻塞消息；不要重复派发。
- 原 owner 偏离或执行风险动作：中断，保存状态并重新确认范围。
- 原 owner 不可恢复：创建新 owner，提供结构化交接包并声明哪些结论仍需复核。

每次重试必须增加证据、改变假设或改变执行条件。重复相同动作且没有预期差异不算有效推进。

## 返工归属

集成后发现原功能内部缺陷时，优先交回原 owner。跨任务契约冲突、合并错误或环境集成问题由主 Agent 或集成 owner 负责。接手前先复现并分类，避免把基线故障误归给最近完成的 Agent。

## 等待与轮询

优先使用当前平台的原生等待、通知或状态查询能力。等待期间主 Agent 保持可响应；不使用长时间阻塞睡眠，也不为一次任务建立无法自动清理的后台轮询。

收到完成消息后仍要核实提交、diff、测试和产物。若用户要求持续监控，约定停止条件，并在完成、取消或明确阻塞后停止轮询。

## 收口

任务完成时记录最终 owner、提交或产物位置、验证证据、尚未解决的问题和后续动作。任务取消或失败时保留可恢复现场，除非用户或项目规则明确要求清理。
